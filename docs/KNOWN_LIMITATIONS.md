# Known limitations — 0.2.1-rc2

- This build is a hardware-test release candidate. Java 25 compilation, source/JAR guards, 212 dependency-free assertions, Gradle/JUnit build, packaged-JAR inspection, and Minecraft 26.2 startup are green, but those gates do not execute a real in-world HyperShot render/capture pass. The target installation still needs actual Photo, Burst, Time, and Cinematic capture tests before this RC can be promoted.
- The Java 25 `IllegalAccessError` path from the old `hypershot$setMainRenderTarget` final-field write remains removed. HyperShot now routes capture-scoped `GameRenderer.mainRenderTarget()` lookups to its private render target without mutating Minecraft's final field. Real-hardware capture is still the required proof for the complete renderer/mod interaction path.
- 32K UHD means 30,720×17,280. It is intentionally marked experimental/high-load until a complete 32K image is captured and its dimensions, file integrity, and restoration behavior are verified on real hardware.
- Cinematic world freeze uses Minecraft's vanilla integrated-server tick-freeze mechanism and is off by default. It has compiled and survived client startup, but a real freeze → capture → restore test is still required before enabling it by default.
- Time mode is singleplayer-only because the server owns authoritative world time. It uses Minecraft 26.2's `WorldClock` system and restores the exact original total-tick snapshot after completion/cancel/failure.
- Cinematic time, weather, and world-freeze controls are authoritative only with the integrated singleplayer server. On multiplayer, HyperShot leaves server-owned state unchanged and keeps only client-side camera/FOV lock, Clean Frame, and nearby-chunk readiness available.
- Cinematic chunk readiness is a client-observed 5×5 area around the player. It checks whether those chunks are present on the client; it does not force server chunk generation, increase the server view distance, or guarantee every distant object needed by a shader is loaded. If the timeout expires, the shot stays blocked until the user explicitly chooses `Capture anyway` or cancels.
- Cinematic camera lock preserves the current player/camera composition and optional FOV while the shot prepares. It is not a detached free-camera, spline/path camera, dolly system, or spectator replacement.
- Shader Settle is best-effort. Temporal/history-based shader packs, auto-exposure, screen-space effects, TAA-like history, cloud history, or other full-screen feedback can still produce tile-local differences because each tile is rendered separately. HyperShot does not claim universal Iris/shader-pack compatibility.
- Burst captures frames sequentially rather than in parallel. This intentionally bounds peak memory and temporary storage but means extreme-resolution bursts can take a long time and are not suitable for high-FPS action photography.
- Time brackets are also sequential. The world is moved through each requested lighting state, allowed to settle according to the configured profile, captured, and then restored; they are not simultaneous exposure brackets.
- OpenGL compilation and Minecraft startup are verified against 26.2. Vulkan uses the same Blaze3D-facing capture architecture, but no Vulkan end-to-end capture run has been completed.
- Pause/resume works between tiles. Final image encoding is not currently interruptible at every individual output row once finalization begins.
- Recovery manifests are written and preserved during active work, but automatic restart/resume of an interrupted capture after relaunch is not exposed yet.
- JPEG is deliberately limited to 20 million pixels because the current JPEG encoder requires a full buffered raster. Extreme-resolution output should use streaming PNG.
- PNG compression/save-effort choices are lossless at every supported level. Higher effort can trade encoding time for smaller files; it does not change visual image quality.
- The Gallery/viewer uses bounded generated previews and contact sheets. Actual-pixel viewing of giant captures is delegated to the operating-system viewer instead of decoding multi-gigabyte images inside Minecraft.
- Native mode performs a clean same-size rerender so capture-only HUD/hand/outline suppression can work without visible flicker. It is not a zero-cost copy of the already-presented framebuffer.
- WebP, TIFF/BigTIFF, EXR, QOI, true HDR/16-bit output, temporal supersampling/accumulation, panoramas, cubemaps, orthographic capture, auxiliary render passes, detached cinematic camera paths, entity masks, and transparent-world rendering are not implemented in this RC rather than being exposed as fake or partial controls.
